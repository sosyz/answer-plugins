# 通行密钥连接器

[English](./README.md) | [中文](./README_CN.md)

> 使用通行密钥（Passkey，WebAuthn / FIDO2）登录 Apache Answer：用指纹、面容、屏幕锁或安全密钥代替密码。

本插件既是一个连接器（显示在其他登录按钮旁边，以及 **设置 > 账号 > 我的登录** 中），也是一个路由插件（提供运行 WebAuthn 流程的页面 `/connector-passkey-auth`）。

## 构建

```bash
./answer build --with github.com/apache/answer-plugins/connector-passkey
```

界面使用 pnpm 9.7.0 构建，即 Answer 核心锁定的版本（`ui/package.json` 中的 `packageManager`）。较新的 pnpm 可能要求先批准 esbuild 和 @swc/core 的构建脚本（`pnpm approve-builds`）后才能安装。

## 快速开始

管理员：

1. 带上本插件构建 Answer（见“构建”），然后重启。
2. 确认 **后台管理 > 设置 > 一般 > 网站网址** 是用户在浏览器中访问的 HTTPS 地址。通行密钥不能在普通 HTTP 下使用，`http://localhost` 除外。
3. 在 **后台管理 > 插件 > 已安装插件** 中启用 **通行密钥连接器**。不需要其他配置；可选配置项见“配置”。

用户：

1. 先用平常的方式登录，例如密码。
2. 打开 **设置 > 通行密钥连接器 > 管理通行密钥**（头像菜单 > **设置**），可以先填一个名称，点击 **添加通行密钥**，再点击 **创建新的通行密钥**。浏览器或设备会请你用指纹、面容、屏幕锁或安全密钥确认。
3. 下次在登录页点击 **连接到 通行密钥**，选择你的通行密钥即可；也可以直接在用户名输入框的自动填充里选择。

## 运行要求

- Apache Answer 2.0.2 或更高版本。插件依赖核心从 2.0.2 开始提供的连接器 OAuth `state`（登录和绑定两种意图）；在更早的版本上，每次登录都会因为缺少 state 而失败。
- HTTPS 的网站网址。浏览器只允许在安全来源上使用 WebAuthn，唯一的例外是用于开发的 `http://localhost`。
- 支持通行密钥的浏览器。浏览器支持时会使用条件式界面（在用户名自动填充中提供通行密钥）。

## 配置

所有字段都是可选的。留空的字段会从网站网址（**后台管理 > 设置 > 一般**）推导，所以网站网址正确的站点无需任何配置即可使用。

| 字段 | 留空时的默认值 | 规则 |
| --- | --- | --- |
| 依赖方名称（`rp_name`） | 网站网址的主机名 | 创建通行密钥时由浏览器或密码管理器显示。 |
| 依赖方 ID（`rp_id`） | 网站网址的主机名 | 纯域名，例如 `example.com`，或 `localhost`。不能带协议、端口、路径，也不能是 IP 地址。 |
| 允许的来源（`rp_origins`） | 网站网址的来源（`scheme://host[:port]`） | 用逗号或换行分隔。每个来源都必须使用 `https`（`localhost` 可以用 `http`），不能带路径、查询参数或片段，并且必须在依赖方 ID 或其子域名下。 |

说明：

- 带子路径的网站网址也可以使用：`https://example.com/community` 得到依赖方 ID `example.com` 和来源 `https://example.com`。
- 部署在反向代理后面时，网站网址必须是用户在浏览器中看到的公开地址，否则来源校验会失败。
- 保存时会拒绝无效的设置。已不再有效的已存设置（例如更改网站网址之后）会保留在后台表单中，接口返回 `503 not_configured`，直到修正为止。
- **更改依赖方 ID 会让所有已有的通行密钥失效。** 认证器把通行密钥绑定在依赖方 ID 上，用户需要重新创建。

## 工作方式

- **登录。** 登录页上的 **连接到 通行密钥** 会打开 `/connector-passkey-auth`，用户在这里选择通行密钥（点击按钮或使用自动填充）。服务端验证后交给核心一个一次性 token，由核心完成登录。
- **关联。** 通行密钥只有关联到某个账号之后，才能登录该账号。管理页上的 **添加通行密钥**（或 **设置 > 账号 > 我的登录** 中的连接按钮）会创建或验证一个通行密钥，并把它关联到当前登录的账号。用尚未关联的通行密钥登录，会进入核心为外部登录准备的新建账号流程。同一用户的所有通行密钥共用一个身份，所以关联是按账号而不是按通行密钥进行的。
- **管理。** **设置 > 通行密钥连接器 > 管理通行密钥** 列出用户的通行密钥，可以添加、重命名和删除，每个用户最多 20 个。已关联账号的最后一个通行密钥，要先在 **我的登录** 中解除通行密钥的关联才能删除；如果通行密钥是某个无密码账号唯一的登录方式，核心会拒绝解除关联。

## 安全

- 连接器只向核心发送一个不透明的随机 ID，从不发送邮箱或个人资料，所以账号只能通过核心的绑定流程关联。
- 伪造的链接无法把通行密钥关联到别人的账号：关联时始终使用核心为当前登录用户生成的绑定 state，登录时服务端要求证明这个 state 是核心为本次登录生成的。
- 要求用户验证和可发现凭据，attestation 为 `none`，签名计数回退时拒绝登录。
- 认证状态经过加密封装且有效期很短，登录 token 一次性使用并与核心 state 绑定，跳转地址由服务端构造。

[SECURITY_CN.md](./SECURITY_CN.md) 详细介绍了设计，以及剩余风险、KV 存储结构，和能消除下面这些限制的核心改动。

## 限制

- 在开启了 **需要登录** 的站点上，核心的路由守卫会阻止匿名访问 `/connector-passkey-auth`，因此无法使用通行密钥登录。
- 核心会把过期的绑定 state 当作登录 state 处理：关联操作如果超过了核心 state 的有效期，会变成一次登录尝试。请重新开始关联。
- 页面从自身 URL 推出界面的基础路径，并认为接口位于同一前缀下（`<base>/answer/api/v1`），这与核心构造所有连接器 URL 的方式一致；不支持单独的接口基础路径。子路径部署尚未经过端到端测试。
- 当界面由 CDN 提供时（例如 `cdn-s3` 或 `cdn-aliyun` 插件），CDN 必须为本站点返回 `Access-Control-Allow-Origin`，因为插件的模块脚本以 CORS 模式加载。见 [cdn-s3](../cdn-s3/README.md) 和 [cdn-aliyun](../cdn-aliyun/README.md) README 中的 CORS 部分。
- 单次使用和唯一性检查只在单个进程内串行化。部署多个 Answer 实例时，仍然存在一些很窄的竞争窗口，见 SECURITY_CN.md。
- 插件 API 没有提供获取当前登录用户的方法，所以插件会读取核心鉴权中间件存放在请求上下文中的用户 ID。如果将来的核心重命名或改变了它的结构，管理接口会返回 `401`，插件会记录一条指出原因的错误日志。
